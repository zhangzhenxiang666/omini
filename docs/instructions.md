# Agent 指令（AGENTS.md）

用 `AGENTS.md` 告诉 Agent 应遵循哪些项目规范、工作流和个人偏好。它适合保存长期约定；本次任务的具体要求直接写在对话中。

## 文件位置

| 层级 | 路径 | 用途 |
| --- | --- | --- |
| 用户级 | `~/.omini/AGENTS.md` | 所有项目共用的偏好与工作方式 |
| 项目级 | `<project>/AGENTS.md` | 当前项目的规范与必要背景 |

项目级文件位于项目根目录。可以手动创建，也可以在项目中使用 `/init` 让 Agent 分析代码后生成或更新。

## 指令如何生效

两个文件都会读取。项目指令与全局指令冲突时，项目指令优先；不冲突的全局指令仍然适用。如果项目指令与当前用户请求冲突，Agent 应先说明冲突。

指令文件使用普通 Markdown，无需 frontmatter。内容应具体、可执行，并在项目约定变化时更新。

## 示例

```markdown
# 项目规范

## 代码风格

- 遵循 Rust 惯用写法
- public API 应有说明用途与约束的文档注释
- 使用中文编写注释

## 工作方式

- 修改前先阅读相关代码
- 保留与任务无关的改动
- 涉及用户可见行为时更新使用文档

## 验证

- 运行受影响 crate 的测试
- 提交前运行 cargo fmt --all --check 和 cargo clippy --workspace
```

## 与权限和 Skills 的关系

`AGENTS.md` 可以约定何时使用工具或技能，但工具能否执行仍由[权限规则](permissions.md)决定。可复用的具体工作流程适合写成 [Skill](skills.md)，再通过 `/<skill-name>` 调用。
